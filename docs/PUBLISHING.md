# Публикация FireUp 0.3.0

Подготовлен набор для публичного выпуска. Создание репозитория и отправка в Mozilla являются отдельными действиями; наличие этих файлов не означает публикацию.

## GitHub

Репозиторий: [tyvor/fireup-optimize](https://github.com/tyvor/fireup-optimize), публичный. Лицензия MIT выбрана автором. Загружать нужно содержимое корня проекта, включая скрытую папку `.github`, исходники, тесты и документацию. Личные резервные копии, профили, экспорты настроек, рабочие каталоги и старые сборки исключены.

Issues должны быть включены. Формы ошибки и предложения находятся в `.github/ISSUE_TEMPLATE/`. Workflow проверяет тесты логики и упаковку; он не выпускает релиз автоматически.

Для Homepage использовать https://github.com/tyvor/fireup-optimize, для Support website использовать https://github.com/tyvor/fireup-optimize/issues. Публичный URL политики данных можно взять со страницы `PRIVACY.md` в репозитории. README пока честно сообщает об отсутствии публичного выпуска. Ссылку на установку добавить после появления настоящей страницы AMO.

## Mozilla

1. Открыть Add-ons Developer Hub и войти в аккаунт автора. Условия разработчика просматривает и принимает сам автор.
2. Выбрать Submit a New Add-on, затем **On this site** для публичного каталога.
3. Загрузить `dist/FireUp-0.3.0-unsigned.xpi`, полученный через Build.ps1. Если 0.3.0 уже отправляли с этим идентификатором, обновлять существующее дополнение и повысить номер версии по требованиям формы, а не создавать дубликат.
4. Исправить ошибки валидатора и рассмотреть предупреждения. Не отмечать Android без проверки. Минимальная версия настольного Firefox в манифесте: 140.
5. При запросе исходников предоставить `FireUp-0.3.0-reviewer-source.zip` из комплекта подготовки: исходники и инструкции сборки. Все исполняемые файлы читаемые, преобразования исходников нет. Публичный GitHub не заменяет файл исходников, если его запросила форма или рецензент.
6. Заполнить карточку текстом из [AMO-LISTING.ru.md](AMO-LISTING.ru.md), выбрать MIT, добавить действующие адреса GitHub и скриншоты с подписями. Объяснение данных находится в [PRIVACY.md](../PRIVACY.md).
7. Вставить [AMO-REVIEWER-NOTES.en.md](AMO-REVIEWER-NOTES.en.md) в Notes for Reviewers. Проверить данные автора и отправить версию.
8. После подписи и появления страницы проверить обычную установку из каталога, внести реальную ссылку AMO в README. Не выдавать неподписанный файл за готовый установщик.

Последующие версии загружать на страницу существующего дополнения. Сохранять идентификатор `fireup@local.extension`, пока используется та же карточка. Разработка на GitHub сама по себе не обновляет установленное расширение: обновление нужно отдельно отправить в Mozilla.

## Что объяснить пользователям

- Перед выгрузкой защитить несохранённый ввод, редакторы и тихое воспроизведение. Содержимое страниц FireUp не читает.
- Работа с адресами и состоянием вкладок локальная. Очередь содержит адреса кандидатов до завершения текущего запуска браузера. В экспорт попадают настройки и исключения доменов.
- GitHub Issues публичные; не отправлять приватные адреса, профили, токены и cookies.
- Размер экономии зависит от страниц и Firefox. Проверка автора в Firefox есть; полного протокола совместимости и гарантированных цифр нет.
